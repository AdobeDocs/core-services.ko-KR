# CDN을 통해 데이터 수집 경로 지정

일부 조직에서는 데이터 수집 요청을 Adobe으로 직접 전송하는 대신 CDN(콘텐츠 전달 네트워크)을 통해 라우팅합니다. 일반적인 이유로는 웹 애플리케이션 방화벽(WAF) 보호, 모든 웹 사이트 트래픽이 CDN을 통과해야 하는 기업 정책 및 Adobe으로 전송된 트래픽을 검사하는 기능이 있습니다. CDN은 조직이 소유하는 호스트 이름에서 요청을 받은 다음 이를 오리진이라고 하는 Adobe 데이터 수집 호스트 이름으로 전달합니다.

>[!IMPORTANT]
>
>Adobe에서 CDN 구성을 검토하거나 확인할 수 없습니다. 조직과 CDN 공급자는 CDN을 올바로 구성할 책임이 있습니다. CDN을 구성하는 데 도움이 필요하면 CDN 공급자에게 문의하십시오. 잘못 구성된 CDN은 데이터 손실을 초래할 수 있습니다.

## 원본 유형 선택 {#origin-type}

| | 서드파티 원본(권장) | 자사 원본 |
| --- | --- | --- |
| **원본 호스트 이름** | `data.adobedc.net`의 테넌트 ID 하위 도메인(예: `example.data.adobedc.net`) | 자사 호스트 이름(예: `data.example.com`) |
| **Adobe 서버의 인증서** | Adobe 인증서(`*.data.adobedc.net`) | [고객 관리 인증서](customer-managed-cert.md) |
| **인증서 갱신** | 필요 없음 | 조직에서 인증서를 갱신하여 각 만료 전에 Adobe에 제공합니다 |
| **지역 잠금 [RDC](rdc.md)** | 지원되지 않음 | 지원됨 |
| **사용 시기** | 조직에서 자사 출처를 필요로 하지 않는 한 모든 CDN 구현 | 보안 정책에 따라 원본 인증서를 직접 제어하거나 조직에 지역 잠금 RDC 유형이 필요합니다 |

>[!NOTE]
>
>[Adobe 관리 인증서 프로그램](adobe-managed-cert.md)은(는) CDN 구현을 지원하지 않습니다. Adobe은 CDN을 가리키는 호스트 이름에 대한 도메인 소유권을 확인하거나 인증서를 갱신할 수 없습니다. 서드파티 원본 또는 [고객 관리 인증서](customer-managed-cert.md)가 있는 자사 원본을 사용하십시오.

## 모든 CDN 구현에 대한 요구 사항 {#requirements}

AppMeasurement 및 Web SDK과 같은 Adobe 데이터 수집 라이브러리는 각 요청에 Adobe에 필요한 모든 것을 포함합니다. 이러한 요청을 변경하지 않고 Adobe에 전달하도록 CDN을 구성합니다.

>[!IMPORTANT]
>
>보고서 세트 ID(AppMeasurement) 또는 데이터 스트림 ID(Web SDK)를 포함하여 데이터의 이동 위치를 결정하는 종단점 또는 어떤 것도 변경하지 마십시오. 이 값을 변경하면 데이터가 손실됩니다.

CDN 구성은 다음과 같아야 합니다.

* 요청 메서드, URL 경로, 쿼리 문자열 및 본문을 변경 없이 전달합니다.
* `Host` 헤더는 그대로 둡니다.
* Adobe 쿠키가 설정된 도메인은 그대로 둡니다.
* 이 안내서의 [쿠키 섹션](cookies/overview.md)에 나열된 모든 쿠키를 유지합니다.
* 방문자의 IP 주소를 포함하는 `X-Forwarded-For` 헤더를 추가합니다. Adobe은 지리적 위치에 이 헤더를 사용합니다. 이 데이터가 없으면 지리적 위치 데이터는 방문자 대신 CDN 서버의 위치를 반영합니다.
* 변경 없이 Adobe의 응답을 브라우저에 반환합니다.

CDN 구성은 다음과 같은 작업을 수행할 수 있습니다.

* 사이트의 다른 시스템에서 쿠키와 같이 Adobe이 사용하지 않는 쿠키를 제거합니다. 관련 없는 쿠키는 모든 요청에 오버헤드를 추가합니다.
* 위에 나열된 것을 변경하지 않는 한 WAF, 보트 필터링 또는 개인 데이터 제거 서비스를 사용하십시오. 프로덕션 트래픽에 적용하기 전에 개발 보고서 세트 또는 데이터스트림으로 이러한 서비스를 테스트하십시오. 지나치게 적극적인 필터링은 보고서를 사용할 수 없게 만들 만큼 충분한 데이터를 제거할 수 있습니다.

CDN 구성은 다음과 같아야 합니다.

* 데이터 수집 요청 또는 응답을 캐시합니다. 모든 요청은 Adobe에 도달해야 합니다.
* 존재하지 않는 원본 호스트 이름을 가리킵니다.
* 만료된 인증서를 수락하거나 원본에서 특정 인증서를 고정합니다. Adobe은 만료된 인증서 제공을 지원하지 않으며 언제든지 제거할 수 있습니다.

## 서드파티 오리진으로 CDN 구성 {#third-party-origin}

서드파티 원본은 Adobe의 자체 인증서를 사용하므로 조직에서 Adobe 서버에서 인증서를 유지 관리할 필요가 없습니다.

1. 조직의 테넌트 ID를 찾습니다. [테넌트 ID 찾기](collection-domain.md#tenant-id)를 참조하십시오.
1. CDN 구성에서 원본 호스트 이름을 테넌트 ID 하위 도메인 `data.adobedc.net`(으)로 설정합니다. 예: `example.data.adobedc.net`.
1. 원본에 대해 SNI(서버 이름 표시)를 활성화합니다. SNI 호스트 이름을 웹 사이트의 호스트 이름이 아닌 원본 호스트 이름(예: `example.data.adobedc.net`)으로 설정합니다.
1. 위의 [모든 CDN 구현에 대한 요구 사항](#requirements)을 충족하도록 CDN을 구성합니다.
1. 구현에서 데이터를 보내는 호스트 이름이 변경되면 [구현을 업데이트](collection-domain.md#update-implementation)하십시오. 동일한 호스트 이름을 유지하는 경우 구현 변경이 필요하지 않습니다.

>[!WARNING]
>
>Adobe이 CNAME 대상으로 제공한 호스트 이름(예: `hiodsibxvip01.data.adobedc.net`)으로 원본을 설정하지 마십시오. 해당 호스트 이름은 자사 인증서에 연결되어 있으며 인증서가 제거되면 작동을 중단할 수 있습니다.

서드파티 원본은 항상 기본 [RDC 유형](rdc.md)을 사용하므로 모든 Adobe 데이터 수집 위치에서 데이터를 수집할 수 있습니다.

## 자사 소스로 CDN 구성 {#first-party-origin}

조직에서 필요로 하는 경우에만 자사 출처를 사용합니다. 일반적인 이유는 다음과 같습니다.

* 보안 정책에 따라 원본 인증서를 직접 제어해야 합니다. 예를 들어 조직에서 자체 인증 기관을 통해 인증서를 취소할 수 있어야 합니다.
* 조직에 지역 잠금 [RDC 유형](rdc.md)이(가) 필요합니다.

1. Adobe 고객 지원 센터에 문의하여 `data.example.com`과(와) 같은 자사 호스트 이름에 대해 [고객 관리 인증서](customer-managed-cert.md)를 설정하십시오. 조직에 지역 잠금 RDC 유형이 필요한 경우 요청에 지정합니다.
1. CDN 구성에서 원본 호스트 이름을 자사 호스트 이름으로 설정합니다.
1. 원본에 대해 SNI(서버 이름 표시)를 활성화합니다. SNI 호스트 이름을 자사 호스트 이름으로 설정하고 원본에서 자사 인증서를 예상하도록 CDN을 구성합니다.
1. 위의 [모든 CDN 구현에 대한 요구 사항](#requirements)을 충족하도록 CDN을 구성합니다.
1. 구현에서 데이터를 보내는 호스트 이름이 변경되면 [구현을 업데이트](collection-domain.md#update-implementation)하십시오. 동일한 호스트 이름을 유지하는 경우 구현 변경이 필요하지 않습니다.

>[!IMPORTANT]
>
>조직은 고객 관리 인증서를 갱신하고 만료되기 전에 Adobe 고객 지원 센터에 제공할 책임이 있습니다. Adobe 서버의 인증서가 만료되면 CDN이 연결을 거부하고 사용자에게 알리지 않고 데이터를 삭제할 수 있습니다. [인증서 갱신](customer-managed-cert.md#renewals)을 참조하세요.

## 기존 자사 구현을 CDN으로 이동 {#migrate}

조직에서 현재 Adobe에서 호스팅하는 인증서를 사용하여 자사 호스트 이름으로 데이터를 직접 전송하는 경우 다음 단계를 사용하여 CDN으로 이동합니다.

1. 모든 Adobe 제품에서 자사 호스트 이름으로 데이터를 전송하는 모든 구현을 식별합니다. Adobe Target 또는 Adobe Journey Optimizer과 같은 다른 제품은 동일한 호스트 이름을 사용할 수 있으며 단일 인증서로 많은 호스트 이름을 사용할 수 있습니다.
1. [원본 유형](#origin-type)을 선택하세요. 자사 원본을 선택한 경우 인증서가 만료되기 전에 Adobe 고객 지원 센터에 문의하여 인증서를 [고객 관리 인증서](customer-managed-cert.md)(으)로 전환하십시오.
1. CDN을 구성합니다. 구현을 업데이트할 필요가 없도록 기존 호스트 이름을 유지하십시오.
1. 인증서가 만료되기 전에 호스트 이름을 CDN으로 지정하고 모든 구현을 전환하여 사용하십시오.
1. [데이터를 확인](#check)합니다.
1. 서드파티 원본을 선택한 경우 Adobe 고객 지원 센터에 문의하여 자사 인증서를 제거할 수 있도록 표시합니다.

호스트 이름이 CDN을 가리키면 Adobe에서 자사 인증서를 갱신할 수 없습니다. 인증서가 만료되어도 구현에서 인증서에 계속 의존하는 경우 해당 구현의 데이터가 손실됩니다. Adobe 고객 지원 센터에 연락하면 인증서가 제거될 때 조직에서 제어할 수 있습니다.

## 데이터 확인 {#check}

Adobe에서 CDN 구성을 확인할 수 없습니다. CDN을 통해 데이터 수집을 라우팅한 후 변경 전후의 데이터를 비교합니다.

* 데이터는 일반적인 볼륨의 예상 보고서 세트, 데이터스트림 또는 데이터 세트에 계속 도달합니다.
* 지리적 위치 보고서는 CDN 서버가 있는 소수의 도시가 아니라 방문자의 위치를 보여줍니다.
* 고유 방문자 수는 예기치 않게 증가하지 않습니다.
* 브라우저의 개발자 도구에서 호스트 이름에 대한 데이터 수집 요청이 성공했으며 Adobe 쿠키가 이전과 동일한 도메인에 설정됩니다.

## 일반적인 구성 오류

다음 문제는 데이터 품질 문제 또는 데이터 손실을 초래하는 것으로 알려져 있습니다. 이 목록은 완전하지 않습니다.

| 증상 | 가능한 원인 |
| --- | --- |
| 보고서 세트 또는 데이터스트림에 데이터 도착이 중지됨 | CDN이 요청 URL을 변경하거나 원본 호스트 이름이 존재하지 않습니다. |
| 인증서가 만료된 후 데이터 도착이 중지됨 | CDN은 원본의 자사 인증서가 예상되며 해당 인증서가 만료됩니다 |
| 지리적 위치 데이터에는 몇 개의 도시만 표시됩니다 | CDN에서 `X-Forwarded-For` 헤더를 추가하지 않습니다. |
| 고유 방문자 수가 예기치 않게 증가합니다. | CDN은 Adobe 쿠키를 제거하거나 `Host` 헤더를 변경하거나 쿠키 도메인을 변경합니다 |
| 보고서에 많은 양의 데이터가 누락되었습니다. | 개인 데이터 제거 또는 WAF 규칙은 각 요청을 너무 많이 제거합니다 |

## 자주 묻는 질문

+++이 페이지는 Adobe Analytics 이외의 제품에도 적용됩니까?

예. 이 페이지는 Customer Journey Analytics, Adobe Experience Platform, Adobe Target 및 Adobe Journey Optimizer을 포함하여 Adobe 데이터 수집을 사용하는 모든 Adobe 제품에 적용됩니다.

+++

+++Adobe이 내 CDN을 통해 전송되지 않는 데이터를 거부할 수 있습니까?

아니요. Adobe은 현재 데이터 수집을 CDN의 요청으로 제한하는 방법을 제공하지 않습니다.

+++

+++Adobe에서 내 CDN에 대한 구성을 제공하거나 확인할 수 있습니까?

아니요. CDN 구성 옵션은 공급자마다 다르고 시간에 따라 달라집니다. CDN 구성에 대한 도움말은 CDN 공급자에게 문의하고, 구성에 문제가 있는지 확인하는 방법은 [데이터 확인](#check)을 참조하십시오.

+++
